# Release readiness review — October 27, 2026

Reviewed release `1b515ed` and recovery changes in this working tree using isolated temporary installations and fictional demo members. Production data and services were not changed. Check scripts remain outside the repository.

## Verified locally

- Full application import and database initialization in manager mode.
- Member, Staff, Unit administrator and unrelated-account access boundaries; cross-unit denial and private roster field exclusion for Members.
- Denial of panel-user administration and hosting control without the required access.
- CSRF, suspended membership, disabled accounts and outdated-session rejection.
- Note edits and stale-note version rejection.
- Personnel lists, member version comparison, template creation and collaboration responses.
- Temporary cover assignment/cancellation preserves primary placement; follow-ups can be created and completed.
- Event creation with explicit end time and formation audience.
- Branding upload/retrieval; unit ZIP exports exclude global accounts and other units and include uploaded attachments.
- Recovery of a custom-path SQLite database with committed WAL data; code rollback preserves newer live records.
- Explicit database restore retains the replaced database; corrupt snapshots are rejected before replacement.
- HTTP readiness accepts the panel login form and rejects unrelated responses.

## Permission review

Recent unit routes in `units.py`, `unit_personnel.py`, `unit_events.py`, `unit_structure.py`, `unit_members.py`, `unit_sops.py` and `roster_tools.py` were inspected for shared authorization. Bulk operations authorize through `bulk_plan`. The unit HTML shell uses global session authorization; unit data is independently checked by the APIs. This is a focused review of recent unit features and shared guards, not a complete security assessment of all hosting integrations.

## Recovery fixes

Updates wait for a local HTTP sign-in response and service activity. Database snapshots require an integrity check and record the configured source path. An explicit offline restore command retains the replaced database. See [backup and recovery](operations.md#backup-and-recovery).

## Outstanding

No supported browser-control tool was connected. Visual alignment, drag/zoom cropping, print dialogs and two-browser collaboration remain unverified. Event creation was exercised; duplication's button/form interaction remains a browser check. Live systemd restarts, failed production updates, game-server launches and real attendance collection were not performed.
